# PredictOps Quality Audit — 2026-10-19

## Implemented in this release
- FastAPI API and interactive single-origin dashboard.
- Four synthetic failure scenarios, rule-based incident diagnosis, capacity what-if, SLO proxy, evidence-grounded incident copilot, A/B remediation simulator, recovery verification and incident replay.
- CSV input validation and bounded data retention in application state.
- Security headers and a fail-closed `ADMIN_API_TOKEN` guard for administrative operations in production/AWS mode.
- Optional AWS CloudWatch CPU read integration; no infrastructure provisioning.
- Optional Isolation Forest, supervised Random Forest incident classifier, and Prophet model-training workflow; reproducible synthetic generator.
- Held-out model evaluation with dataset SHA-256, provenance, confusion matrix and comparison against transparent threshold rules.
- GitHub Actions CI for backend, model evaluation, JS syntax, and real Chromium/WebGL smoke tests.

## Synthetic holdout results (not production claims)
- Isolation Forest: precision 0.5325, recall 0.6406, F1 0.5816, accuracy 0.9213 on 750 chronological holdout rows.
- Supervised Random Forest classifier: precision 0.9683, recall 0.9531, F1 0.9606, accuracy 0.9933 on the same 750 chronological holdout rows; labels were generated by the synthetic scenario generator, so this is not production accuracy.
- Fixed threshold-rule baseline: precision 0.7529, recall 1.0000, F1 0.8591, accuracy 0.9720 on the same holdout.
- Persistence forecast baseline: MAE 24.4394, RMSE 28.6776.
- Linear trend forecast baseline: MAE 27.7128, RMSE 31.8500.

The simple threshold baseline performs better than Isolation Forest on this synthetic dataset. This should be reported honestly and used as a research finding, not hidden. Prophet was not installed in the local audit environment and was not evaluated. The supervised classifier performs strongly because synthetic labels are generated from distinctive anomaly patterns; evaluate on independently labelled real telemetry before making operational claims.

## Not verified / still required for a top-tier final-year submission
- The browser navigation policy in this execution environment blocks navigation to the local Uvicorn server. Therefore the included strict Playwright browser test has **not** been passed here. It is wired into GitHub Actions to verify the actual WebGL renderer and UI interactions in a normal CI browser environment.
- No public Render deployment has been created or verified; the blueprint is only prepared.
- No live AWS account was accessed and no Lambda remediation was executed. AWS mode remains local by default and cloud remediation disabled by default.
- Metrics in the demo are synthetic unless explicitly sourced from AWS CloudWatch. CloudWatch integration currently imports EC2 CPU only.
- Forecasting remains a linear baseline unless an optional Prophet model is trained and evaluated.
- Root-cause analysis is rule correlation, not causal inference. SLO error-budget values are educational proxies, not production SLO measurements.
- JSON state is single-demo state and may be ephemeral on free hosting; it is not a production multi-user database.

## Release criteria before claiming end-to-end completion
1. GitHub Actions backend and browser/WebGL jobs pass.
2. Public URL is reachable and browser console is clean; public UI workflows work.
3. Admin token guard is tested on the deployed service.
4. Read-only CloudWatch metrics are validated against an existing, low-cost demo target.
5. If live remediation is in scope, dedicated Lambda invocation, IAM least privilege, audit evidence and recovery verification are demonstrated with explicit operator approval.
